ZWEDGE LOST-WAKE slot=0 zcw=0x60085471e100 blocked_ms=418.3 zcw_done=1
A backend blocked in the UNTIMED cv_wait(&zcw->zcw_cv). Its zcw_done==1 => zil_commit_waiter_done
ALREADY ran (set zcw_done=TRUE, called cv_broadcast). Yet 418ms later the waiter is STILL ASLEEP.
The completion RAN + the waiter is STILL ASLEEP = LOST OSv condvar wakeup. NOT an upstream ZFS hang
(that would show zcw_done=0). Only ONE line because post-wedge zil_commit_waiter_done stops being
called (all commits deadlocked), so the watchdog stops scanning.
Combined with FLUSH_INLINE=1 STILL WEDGES + WAKE_IPI_ALWAYS=1 STILL WEDGES: the wake is lost in the
cv_broadcast->condvar_wake_all->mutex::send_lock->unlock->other->wake() WAIT-MORPHING handoff on
zcw_lock, or thread::wake_impl's waiting->waking CAS - BEFORE send_wakeup_ipi.

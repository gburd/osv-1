STEP 2b -- VICTIM VA DECODE (decisive: names the memory region)
================================================================================
OSv memory map (include/osv/mmu-defs.hh): mem_area_size = 1<<44, base =
0x400000000000 | (area<<44).  The THREE identity-mapped areas alias the SAME
physical RAM at three different VAs (translate_mem_area just rewrites top bits):
  area 0 mem_area::main     = 0x400000000000  (physical/identity map; DMA uses this)
  area 1 mem_area::page     = 0x500000000000
  area 2 mem_area::mempool  = 0x600000000000  <-- VICTIM LIVES HERE
  area 3 mem_area::debug    = 0x700000000000

Victim VA 0x6001087d5fe0  ->  mem_area::mempool (the small-object malloc heap).
It is IDENTITY-MAPPED and shared verbatim across every fork AS (slot >
pml4_app_last=127 => kernel slot, cloned as parent_pml4[slot] verbatim).  So the
victim is NOT COW-divergent; it is a genuine SHARED small heap object
(a forked PG backend thread's detached_state) that got WILD-WRITTEN.

WHY THIS MATTERS FOR THE WRITER:
The mempool (0x6000..), main (0x4000..), and page (0x5000..) areas are three VA
ALIASES of the same physical pages.  A wild 128KiB write issued through the
0x4000.. (main/physical/DMA) alias to a WRONG physical offset lands on whatever
object occupies that phys page and is observed as corruption at the 0x6000..
mempool alias (the detached_state) OR on disk (if it is the DMA source/dest that
is wrong).  This unifies the on-disk 128KiB corruption (signatures A/B/C) and
the in-memory scheduler-object clobber (signatures D/E, this capture): ONE wild
writer using a wrong physical/main-area address or length.

  => The corruptor is a write whose DEST (physical addr) or LENGTH is
     miscomputed in the AS0 ZFS completion/txg_sync path -- Agent B's #1a DEST
     leg / #2 gang-header DVA / a bio bio_offset/bcount, NOT the ABD source leg
     (#1c ruled out: WALL3_ABD_ARENA silent).

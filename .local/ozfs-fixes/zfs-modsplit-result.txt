GOAL
----
Restructure PR #1423's in-kernel ZFS into the module layout wkozaczuk requested
(issue #1201): a `zfs` placeholder module plus `bsd_zfs` and `open_zfs` modules
that each PROVIDE `zfs`, mirroring how `java` is provided by
openjdk8-from-host / openjdk9_1x-from-host. Build-structure refactor only; the
same objects build for each ZFS mode. conf_zfs=bsd (default) -> bsd_zfs;
conf_zfs=openzfs -> open_zfs.


THE PROVIDE / PLACEHOLDER MECHANISM (as found in the codebase)
-------------------------------------------------------------
scripts/osv/modules/resolve.py:require() registers a module under its own name,
then, if it declares `provides = [...]`, ALSO registers it under each provided
name (raising if that name is already taken). A "placeholder" module (e.g.
modules/java/module.py) carries NO `provides`; instead its module.py calls
api.require(<concrete provider>). Because the placeholder requires its provider
DURING its own import - before resolve assigns the placeholder's own name - the
provider's `provides=['zfs']` claims the `zfs` name first (guard passes), then
the placeholder overwrites _modules['zfs'] with itself. No collision. This is
exactly how `java` works, and it is what I reused for `zfs`.

conf_zfs is selected on the make/build command line and scripts/build exports
every `name=value` arg into module.py's environment (scripts/build ~line 276),
so module.py reads os.environ.get('conf_zfs','bsd') - the same way the existing
modules/zfs-tools/module.py already does.

An important structural fact: OSv's build has two stages. Stage 1 is the kernel
Makefile, which compiles the ZFS objects and links libsolaris.so (a kernel-side
artifact, a bootfs_dep). Stage 2 is scripts/module.py, which orchestrates the
`modules` (module.py + manifests). Module app-Makefiles do NOT build kernel .so
objects. So the ZFS object/link RULES cannot literally live in a module
app-Makefile; the faithful move is to extract them into .mk fragments OWNED BY
each module and `include`d by the top-level Makefile. That is what was done.


WHAT MOVED WHERE
----------------
modules/zfs/  (PLACEHOLDER)
  - module.py (NEW): reads conf_zfs; api.require('open_zfs') if openzfs else
    api.require('bsd_zfs'). Carries no `provides`.
  - usr.manifest (unchanged): still ships /usr/lib/fs/libsolaris.so - the one
    manifest entry BOTH implementations share.

modules/bsd_zfs/  (PROVIDES zfs; conf_zfs=bsd)
  - module.py (NEW): provides = ['zfs'].
  - bsd_zfs_sources.mk (NEW): the legacy BSD/Illumos ZFS build rules moved
    verbatim out of the top-level Makefile - the `solaris` compat-object list,
    the `zfs` core-object list (both shared/base), and the conf_zfs=bsd
    object/flag selection (solaris += $(zfs); the avl/nvpair/unicode/fm/list
    objects BSD needs its own copies of; the BSD $(zfs)/$(solaris) CFLAGS +
    ASFLAGS). Included UNCONDITIONALLY by the top-level Makefile because it
    defines the shared solaris/zfs lists both modes build on.

modules/open_zfs/  (PROVIDES zfs; conf_zfs=openzfs)
  - module.py (NEW): provides = ['zfs'].
  - open_zfs_sources.mk (RENAMED from bsd/sys/cddl/openzfs_sources.mk via
    git mv, + EXTENDED): keeps all the OpenZFS 2.4.x object lists
    (openzfs-zfs/icp/lua/zstd/... = $(openzfs-all)) and the OPENZFS_INCLUDES /
    OPENZFS_CFLAGS / OPENZFS_LUA_CFLAGS definitions, and now ALSO carries the
    conf_zfs=openzfs object/flag selection that used to sit in the top-level
    Makefile: solaris += $(openzfs-all); filter-out the ABI-incompatible
    opensolaris_kstat.o stub; the OpenZFS -fPIC/-DBUILDING_ZFS CFLAGS; the
    zfs_initialize_osv.o -fPIC rule; the Lua/ZSTD include tweaks; the
    openzfs-icp-asm ASFLAGS override.
  - openzfs/ (submodule, unchanged) + patches/ (unchanged, applied at build).


TOP-LEVEL Makefile CHANGES (~207 lines removed, replaced by includes)
---------------------------------------------------------------------
1. The big ZFS object/flags block (was ~lines 766-970) is replaced by:
       include modules/bsd_zfs/bsd_zfs_sources.mk        # always: defines solaris/zfs
       ifeq ($(conf_zfs),openzfs)
       include modules/open_zfs/open_zfs_sources.mk      # swaps in $(openzfs-all)
       endif
   Ordering is correct: bsd_zfs defines `solaris` first, then (for openzfs) the
   open_zfs fragment appends $(openzfs-all) and sets OpenZFS flags. Nothing
   between the header and the object block references any openzfs-* variable, so
   moving the OpenZFS include down from the header to here is safe (verified).
2. The header's inline `include bsd/sys/cddl/openzfs_sources.mk` was removed
   (relocated as above). The OpenZFS patch-apply $(shell ...) block and the
   `$(out)/tools/mkfs/mkfs.o: CXXFLAGS += -DCONF_ZFS_OPENZFS` redirect STAY in
   the top-level Makefile (kernel plumbing, not module-owned build rules).

KERNEL IMPL-AGNOSTIC BITS - LEFT IN PLACE (unchanged)
-----------------------------------------------------
openzfs_cv_timedwait, the -DCONF_ZFS_OPENZFS per-object redirect, pagecache
bridge symbols, drivers/zfs.o, fs/zfs/zfs_null_vfsops.o, and the OpenZFS

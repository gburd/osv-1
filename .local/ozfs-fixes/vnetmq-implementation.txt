Design notes:
  * Queue layout per spec: rx[i]=vq 2*i, tx[i]=vq 2*i+1, ctrl=vq 2*max_pairs.
  * MSI-X entry == virtqueue index (setup_queue() maps 1:1); each Rx vector wakes
    its own pinned poll thread -> N receivers run in parallel across CPUs.
  * nqp==1 path (no F_MQ, or MMIO shared IRQ) is behaviourally identical to the
    original single-queue driver.
  * The MSI-X vector budget fixes the pre-existing high-vCPU boot crash: the
    x86-64 IDT has only 224 usable vectors (32..255) shared by every device;
    several multiqueue virtio devices at high vCPU counts exhausted them and
    aborted at driver load. Now each device caps its interrupt-bearing queues
    against a shared pool and the allocator degrades instead of aborting.

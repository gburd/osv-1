RESULT: faulting symbol / lookup path
  The lazy PLT resolver path a forked child runs is:
    __elf_resolve_pltgot -> elf::object::resolve_pltgot(index)
      -> object::symbol(idx)             (core/elf.cc)
        -> program::lookup(name, this)   (iterate modules_get() list)
          -> module->lookup_symbol(name) (GNU-hash walk of each object)
    on a null result: abort("%s: failed looking up symbol %s") at elf.cc:729.
  Target symbols (from the prior wave, verified as genuine kernel exports in
  loader.elf .dynsym: T sem_wait@0x403f6520, T pwritev, T preadv; postgres has
  them as normal UND refs). postgres is a lazy-binding PIE (no BIND_NOW), 266
  JUMP_SLOT PLT entries, so a forked backend that first-calls sem_wait/preadv/
  pwritev resolves them IN THE CHILD's COW address space.

RESULT: root cause (what is fork-fragile)
  The whole LAZY-PLT-resolution-across-fork path is the hazard, of which the
  symbol-lookup failure is the second facet (the GOT-slot NULL-deref fixed in
  8d775cc01 is the first).  When a forked child is the FIRST to resolve a PLT
  slot, it runs the resolver in its own COW AS; the resolver touches shared
  linker state (the GOT page, the module/symbol-lookup structures) that is not
  guaranteed coherent across the COW fork boundary.  8d775cc01 fixed the
  GOT-page residence + the _used_by_resolve_plt_got set-node heap; the
  symbol-lookup facet remained because a child was still ENTERING the resolver.
  I confirmed by instrumentation (see A/B) that forked children DO run the lazy
  resolver 100s of times under fork load; every such entry is a fork-coherence
  hazard.  I could NOT reproduce an actual "not found" abort with minimal tests
  (a small binary's whole .dynsym/.gnu.hash/GOT is resident, so its child
  resolver never hits a non-resident/incoherent structure) -- exactly the size
  dependence the GOT-slot facet also had. The correct-by-construction fix is to
  stop the child from entering the resolver at all.

RESULT: the fix (laziest correct, CONF_fork-gated)
  core/elf.cc object::relocate_pltgot(): under CONF_fork force bind_now=true, so
  every PLT jump slot is EAGERLY resolved in AS0 at LOAD time, before any fork.
  Consequences:
    - No forked child ever runs elf::object::resolve_pltgot / program::lookup
      => both fault facets (GOT-slot NULL-deref AND symbol-lookup "not found")
      are removed by construction, not merely patched.
    - Each eager resolution WRITES the GOT slot -> the page becomes anonymous +
      resident -> clone_address_space() COW-shares the RELOCATED contents.
    - It runs inside relocate_pltgot(), BEFORE fix_permissions() write-protects
      the RELRO segment, so the slot writes never hit a read-only page (the
      failure an earlier POST-fork eager-bind attempt hit at 0x100000031e00).
  Uses the pre-existing bind_now code path in relocate_pltgot() (with
  symbol(sym, /*ignore_missing=*/true), so an unresolvable slot is left lazy,
  never aborts at load) -- a 1-line behavioral change under #if CONF_fork.

  SUPERSEDES / MERGES with 8d775cc01: this supersedes the mmap_populate-of-
  writable-segments half (the bind-now writes already pin the GOT resident) and
  is complementary to its identity-heap _used_by_resolve_plt_got insert (that
  now only matters for objects dlopen'd AFTER the first fork -- rare, but kept).
  A reviewer MAY drop the mmap_populate half for minimalism; I left it as a
  cheap belt-and-suspenders for .data.rel.ro pages bind-now does not touch.

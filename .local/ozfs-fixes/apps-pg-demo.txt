This is a clean, self-contained osv-apps module. Unlike the earlier rough
starting point (a module.py + usr.manifest hardcoding build-machine paths like
/b/pgm/install/...), this app follows the osv-apps convention exactly: a
Makefile drives a build.sh that fetches PostgreSQL 18 from source, builds it
with musl-gcc, initdb's a small demo cluster, builds the boot-time seed_copy
helper, and emits usr.manifest referencing only ${MODULE_DIR} (relative build
output) -- no absolute build-machine paths.


================================================================================
1. THE MODULE (files, all source-only; everything else is generated)
================================================================================
apps/postgres18-musl/
  Makefile      -- osv-apps entry point; `make` runs ./build.sh.
  build.sh      -- fetch PG18 source, patch (2 OSv neuters), configure+build
                   with musl-gcc as a PIE, build seed_copy, initdb the demo
                   cluster (demo DB + greetings table), emit usr.manifest.
  seed_copy.c   -- tiny libc-only helper: recursive rofs->ramfs cluster copy
                   at boot (OSv images have no `cp -a`).
  module.py     -- boot command: mount ramfs /data, seed_copy, run postgres.
  README.md     -- the demo + an honest table of every OSv deviation and when
                   each is expected to be erased.
  .gitignore    -- ignores generated src/ build/ install/ seed_copy usr.manifest.

Generated by build.sh (NOT in the tarball / NOT committed):
  src/ build/ install/ (incl. install/data-seed/ baked cluster) seed_copy usr.manifest emptydir

2. HOW IT BUILDS
================================================================================
Prereqs (fedora:39 build container): musl-gcc musl-devel readline-devel,
perl-FindBin, plus the standard OSv build deps (scripts/setup.py) and qemu-kvm.

(a) Build just the app module (fetch + build PG + initdb + manifest):
      cd apps/postgres18-musl && make
    Observed clean-room run (source-only dir -> full build), 40s on 96 cores:
      patched main.c check_root
      patched miscinit.c checkDataDir
      == configuring (CC=musl-gcc) ==
      == building (-j96) ==
      == built:  ELF 64-bit LSB pie executable, x86-64 ...
                 interpreter /lib/ld-musl-x86_64.so.1 ...
      == building seed_copy ==
      == initdb demo cluster ==
      == seeding demo data ==
      CREATE DATABASE
      CREATE TABLE
      INSERT 0 3
      == writing usr.manifest ==
      == done. postgres18-musl app built. ==
      install/bin/postgres: ELF 64-bit LSB pie executable, x86-64 (musl PIE)

(b) Build the OSv image with the app (kernel needs conf_fork=1 for PG's
    fork-per-connection model; fs=ramfs so /data is writable):
      ./scripts/build -j$(nproc) conf_fork=1 fs=ramfs image=postgres18-musl
      -> build/last/loader.elf (178M), build/last/usr.img (54M)

The generated usr.manifest (relative paths only, no /b/pgm):
------------------------------------------------------------
# musl PostgreSQL 18 on OSv -- demo module.
# The read-only cluster is baked at /data-seed; at boot seed_copy copies it into
# a writable ramfs at /data (see module.py).
/usr/bin/postgres: ${MODULE_DIR}/install/bin/postgres
/usr/bin/seed_copy: ${MODULE_DIR}/seed_copy
/usr/lib/**: ${MODULE_DIR}/install/lib/**
/usr/share/**: ${MODULE_DIR}/install/share/**
/data-seed/**: ${MODULE_DIR}/install/data-seed/**
# empty mount point for the writable ramfs /data (rofs cannot mkdir at runtime)
/data: ${MODULE_DIR}/emptydir
------------------------------------------------------------

The baked module.py boot command:
      --mount-fs=ramfs,/dev/null,/data
      /usr/bin/seed_copy /data-seed /data ;
      /usr/bin/postgres -D /data

================================================================================

$ psql -h 127.0.0.1 -p 5432 -U postgres -d demo -c 'select 1 as one;'
 one 
-----
   1
(1 row)

$ psql -h 127.0.0.1 -p 5432 -U postgres -d demo -c 'select * from greetings order by id;'

----+------------+------------------------
  1 | osv        | hello from a unikernel
  2 | postgres18 | stock musl build
  3 | demo       | this row came over TCP
(3 rows)

CREATE TABLE
INSERT 0 3
 total 
-------
    60
(1 row)

$ psql ... -c 'select count(*) from greetings;'

     3
(1 row)

ERROR:  relation "nope" does not exist

That is a full query pipeline over the wire across multiple sequential
connections: a constant, 3 real baked rows, a REAL WRITE PATH (CREATE TABLE +
INSERT of 3 rows + SUM aggregate = 60), a count, and a genuine PostgreSQL error
response (fully processed query, not a crash).


================================================================================
5. WHAT WORKS vs WIP (honest)
================================================================================
WORKS -- single-backend query serving:
  The image boots stock musl PostgreSQL 18.4 to "ready to accept connections"
  and serves real SQL (SELECT, DDL, DML, aggregates, error responses) over TCP.
  Sequential psql connections are reliable. The rows in section 4 are from a
  booted OSv guest, not a host build.

WIP -- sustained multi-backend concurrency:
  PostgreSQL's postmaster forks a backend per connection. OSv fork()/COW
  cross-address-space coherence is a separate, active OSv KERNEL effort
  (fork-arena line of work, PR #1455 family). This DEMO is intentionally scoped
  to single-backend serving; hammering it with many concurrent connections can
  still trip the fork/reap lifecycle wall being fixed in the kernel separately.
  The app module itself is unchanged by that work -- it is the userspace half.

  NOTE ON THE KERNEL: stock cloudius-systems/osv master (cb8c7205) does NOT yet
  contain the fork/COW coherence fixes. On such a tree the postmaster boots but
  a forked backend hits "could not open shared memory segment" (DSM ENOENT) and
  no query is served. The boot+query evidence above was produced on an OSv tree
  carrying those fixes (conf_fork=1, tip 858dd78f2). The README states this
  requirement explicitly. This app is PR-ready for osv-apps as the userspace
  demo; it lights up fully once the kernel fork work lands.

6. OSv DEVIATIONS FROM STOCK PostgreSQL (all workarounds, all tracked to erase)
================================================================================
Build flags (build.sh step 3):
  CC=musl-gcc                          OSv libc is musl (intrinsic to target).
  --without-icu/zlib/readline/lz4/     optional libs not baked into the demo
    zstd/libxml                        image; add back when packaged for OSv.
  -DWAIT_USE_SELF_PIPE                 OSv epoll/signalfd latch path incomplete;
                                       use PG's portable self-pipe latch.
  LDFLAGS_EX=-pie                      OSv runs apps as PIEs (intrinsic).

Source neuters (build.sh step 2 -- two one-line `if (0 && ...)` guards):
  check_root() in main.c               OSv app runs as uid 0; no unpriv user.
  checkDataDir() perms in miscinit.c   OSv fs does not report Unix dir modes.

Cluster config (baked into postgresql.conf / pg_hba.conf):
  initdb --locale=C                    musl has only the C locale.
  io_method = sync                     OSv async-I/O path incomplete.
  unix_socket_directories = ''         OSv has no AF_UNIX; TCP only.
  listen_addresses = '*' + trust hba   demo reachability over forwarded TCP.

Bring-up fixes that are part of THIS app (not deviations from PG, just OSv
image-packaging correctness), all shaken out and now clean:
  * map install/share -> /usr/share (PG relocates sharedir relative to the
    binary at /usr/bin; the timezone db lives under sharedir).
  * .keep markers in empty cluster subdirs (OSv manifest ** globs drop empty
    dirs; PG needs pg_notify, pg_dynshmem, pg_wal/archive_status, ... to exist).
    seed_copy skips materializing .keep so pg_tblspc stays a clean empty dir.
  * build.sh runs `make -C src/backend generated-headers` before the parallel
    build (a fully clean `make -jN` can race src/common ahead of the generated
    catalog/errcode headers).

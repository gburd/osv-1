BOTTOM LINE
-----------
Corruptor #2 is the PAGE-PATH sibling of corruptor #1: the small-object pool's
lock-free MPSC cross-CPU garbage queue (unordered_queue_mpsc) writes an intrusive
free_object::next link (an 8-byte 0x500 mem_area::page-alias pointer) INTO a pool
backing page during a window in which that page has already been returned to
page_pool and recycled into a live 4096B object (a ZFS abd read-chunk, a
range_tree btree leaf, a thread TCB/TLS block).  The stale 8-byte store is the
wild write: it corrupts range_tree metadata (the VERIFY3U(start<end),
const end=0x804000000), ARC read buffers (the EIO on vacuum/checkpoint reads),
and the per-thread TLS s_current slot (the migrate_disable/preemptable assert).
#1's fix hardened the pool's OWN deferred page release; #2 closes the residual by
QUARANTINING every freed page briefly before page_pool can recycle it, so any
in-flight MPSC next-link store drains onto a not-yet-reused page.

=== REPRO CONFIRMED (this base, this session) ===
Fresh 8k lz4 single-file pool, -smp4 -m32G KVM. pgbench -i -s1000 then -c16 -T120.
Every pre-fix run: EITHER migrate_disable/preemptable page-fault assert (TLS
s_current clobbered to 0x40), OR range_tree class, OR EIO storm on read
("could not read blocks ... EIO") during vacuum/checkpoint, OR lost-wakeup hang.

=== VICTIM ADDRESS (localized) ===
RUN B (gdb): faulting thread CPU#2, its own TCB = 0x40010036d980; the TLS block
(kernel_tls_size=2368) at 0x40010036d040..d980 was overwritten; s_current slot
(0x40010036d088) held 0x40 -> thread::current()=0x40 -> migrate_disable() faulted
in memory::page_pool::l1::refill (mov %fs:s_current,%rax ; addl $1,0xe8(%rax)).

=== WRITER PC / FINGERPRINT (named) ===
poison-on-free + verify-on-alloc canary caught the stale writes prolifically (a
plain cpiod/mkfs boot fires 35+):
  off=64,   val = <page>|page-area   (page's own mem_area::page self-alias)
  off=1128, val = <page>|page-area+0x428   == CORRUPTOR #1's EXACT RUN-3 signature
These offsets are free_object slots; the value is std_malloc's page-branch return
(translate_mem_area(main,page,alloc_page())).  Writer = unordered_queue_mpsc::push
"item->next = _head" (and pop()'s "_poll_list = r->next" look-ahead) in the pool's
cross-CPU garbage path (core/mempool.cc garbage_sink / free_different_cpu ->
queue.push).  Confirmed by: (a) offsets/value match a free_object link exactly;
(b) it hits pages that were freed via free_page(); (c) delaying free_page reuse
(quarantine) makes the corruptor vanish.

=== ROOT CAUSE ===
A pool backing page reaches page_pool (via pool::flush_empty_pages ->
untracked_free_page, or is recycled and re-grabbed by pool::add_page) while a
producer on another CPU is mid-push (item->next store) or the consumer's
_poll_list look-ahead still dereferences an object in it.  The 8-byte next-link
store then lands in a page page_pool has already recycled into a live object.
#1 deferred the pool's own release to a drained point; a concurrent producer push
plus the pop look-ahead leave a residual window this fix closes.

=== THE FIX (core/mempool.cc, gated CONF_fork) ===
Bounded per-CPU page-reclaim quarantine in memory::free_page(): a freed page is
parked in a per-CPU ring of PGQUAR_DEPTH=512 pages and only handed back to
page_pool after 512 subsequent frees, so any in-flight MPSC next-link store drains
onto a page that is not yet a live object before recycling.  Bounded (2 MiB/CPU) so
a free storm cannot pin unbounded memory.  Entirely under #if CONF_fork; conf_fork=0
is byte-identical to stock OSv (free_page skips the block).

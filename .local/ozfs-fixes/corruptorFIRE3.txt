=== MECHANISM (page-pool cross-CPU free path; CONF_fork/fork-arena era) ===
The wild write is an 8-byte mem_area::page pointer stored into a page that
page_pool::l2 had already recycled.  The pool small-object allocator
(core/mempool.cc) frees cross-CPU objects through an intrusive lock-free MPSC
queue (lockfree::unordered_queue_mpsc<free_object>, garbage_sink) whose `next`
links live INSIDE the freed objects' pages:
  push():  item->next = old; CAS(_head,...)          // writes link into object/page
  pop():   r=_head.exchange(0); _poll_list=r->next    // reads link from object/page
collect_garbage() pops and calls pool::free_same_cpu(obj); when a page's nalloc
hits 0 and other full pages exist, free_same_cpu does untracked_free_page() ->
the whole page goes back to page_pool::l2.  The MPSC internals (_poll_list, or a
concurrent producer's item->next store) can still reference an object on that
page -> stale 8-byte pointer store/read into the recycled page = the page-level
UAF that later trips the boost intrusive assert in page_range_allocator::alloc.

Recent commits on this branch are the fork stack (594e759c fork COW arena,
07cc861d cross-AS ZFS I/O coherence).  The fork arena moved *application* heap
out of the shared kernel pool for exactly this "child scribbles shared heap"
reason; the cross-CPU page-reclaim path in the shared pool is the same hazard
class, still open.  CLASSIFICATION: [fork-stack] (CONF_fork), not [#1423/OpenZFS].

STATUS: corruptor NAMED (page_pool cross-CPU free/reclaim of shared pool pages).
Two candidate write sites (concurrent producer item->next store; or _poll_list
stale traversal).  To pin the exact store before fixing: hardware watchpoint on
the poisoned page @off 1128 (0x500 alias) — next step.  Candidate fix: stop
pool::free_same_cpu from returning pages to page_pool while cross-CPU frees to
that pool may be in flight (keep empties on the pool _free list; bounded, reused).

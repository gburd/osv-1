WHAT ACTUALLY BLOCKED CONCURRENT LOAD (empirically, not just the two symbolized
walls the prior report predicted) -- FOUR distinct cross-AS coherence bugs, all
100%-or-racily reproducible, all fixed:
================================================================================

(A) epoll_file runtime containers landed in the COW fork arena, freed cross-AS
    by the RCU thread -> arena chunk-magic abort.  [THE primary concurrent wall;
    100% reproducible.]
    Signature (tst-fork-timer-park-stress on HEAD, every run):
      Assertion failed: h->magic == chunk_magic (core/fork_arena.cc: recover:257)
        fork_arena::free(void*)+72
        epoll_file::~epoll_file()+310            <- RCU quiescent-state thread (AS0)
        osv::rcu::cpu_quiescent_state_thread::do_work()
    Root cause: epoll_file is created on the identity heap (make_file wraps its
    ctor incl. the 512-slot _activity_ring), but its RUNTIME containers -- `map`
    (registered fds) and `_activity` (ready fds) -- grow their nodes on whichever
    thread runs epoll_ctl / epoll_wait / a poll waker.  Under fork that thread is
    a child BACKEND whose allocations land in its COW fork arena, so each address
    space gets a PRIVATE node.  The file is RCU-reclaimed by the quiescent-state
    thread in AS0, whose ~epoll_file() then frees those child-arena nodes -- but
    an arena chunk written by a child is garbage in AS0's view, so fork_arena::
    free() trips its chunk-magic assert and aborts the whole VM.  PostgreSQL hits
    this within seconds under sustained concurrent epoll load (every backend
    epoll_waits on its latch self-pipe + client socket).
    FIX (core/epoll.cc, #if CONF_fork): force every `map`/`_activity` node
    allocation onto the identity kernel heap (EPOLL_KH() = kernel_heap_scope
    around each mutation: add(), wake(), flush_activity_ring(), the wait()
    move-back) so all address spaces share ONE coherent set of nodes, freeable
    from AS0 -- the same rule as struct file / f_epolls / thread objects.
    Non-fork: EPOLL_KH() is a no-op; behavior byte-identical.

(B) rcu_defer's on-stack wait_record walked cross-AS by the RCU thread ->
    page fault in non-preemptable context.  [Revealed after (A); ~40% of runs.]
    Signature:
      page fault outside application, addr: 0x0000200000c01fa8 (child stack VA)
        memory::page_pool::l2::refill()  (on a fork-child pthread stack)
      Assertion failed: sched::exception_depth <= 1
        (core/sched.cc: reschedule_from_interrupt:288)
      ... via osv::rcu::cpu_quiescent_state_thread::do_work()+151
    Root cause: when the per-CPU rcu_defer callback queue fills, rcu_defer()
    parks the caller on an ON-STACK `wait_record wr` linked into
    *percpu_waiting_defers.  The RCU quiescent-state thread (AS0, preemption
    DISABLED) later walks that list (q->next, q->wake()).  For a fork-child
    caller wr lives on the child's stack (COW/app-slot VA), unmapped in AS0 ->
    a page fault in non-preemptable context aborts the VM.  PG fills the queue
    under sustained load (fd/relcache teardown, snapshot RCU).
    FIX (core/rcu.cc, #if CONF_fork): allocate the record via
    coherent_wait_record (identity kernel heap for a fork child, on-stack fast
    path for AS0) -- the SAME rule condvar / lockfree::mutex / waitqueue use.

(C) THE LOST-WAKEUP that wedged concurrent WRITERS: OSv reported ONE pid
    (OSV_PID) for every forked backend, defeating PostgreSQL's cross-backend
    latch wakeup.  [Symbolized via pg_stat_activity, not a crash.]
    Symptom: `pgbench -c 4` ran ~5 tps for 5 s then 0 tps forever, 0 failed, VM
    alive (a fresh `select 42` is served while the bench is wedged).
    pg_stat_activity: all 4 backends "active", wait_event = Lock:transactionid,
    and every backend logged pid = 2.
    Root cause: PG's latch layer (WAIT_USE_SELF_PIPE build) wakes a waiter with
    SetLatch(): storage/ipc/latch.c:342 does
       else if (owner_pid == MyProcPid) sendSelfPipeByte();   // LOCAL
       else                             WakeupOtherProc(owner_pid); // kill(pid,SIGURG)
    MyProcPid = getpid().  OSv's getpid() returned the constant OSV_PID (=2) for
    EVERY backend, so a backend releasing a lock and waking a DIFFERENT waiting
    backend saw owner_pid == MyProcPid (2==2) -> took the LOCAL path and poked
    its OWN self-pipe.  The waiting backend's self-pipe is never written, its
    epoll_wait never returns, and the heavyweight-lock wait wedges forever (no
    PG-level deadlock: the holder DID release; the wakeup was simply lost).
    FIX, three coordinated pieces (all #if CONF_fork; AS0/top-level keep OSV_PID
    so the non-fork path is byte-identical):
      * runtime.cc getpid() -> osv::fork::pid_for_current(): each fork child
        reports its own DISTINCT pid (its child thread id -- exactly what fork()
        returned to the parent), keyed by address space.
      * libc/process/fork.cc: a pid<->address-space registry (g_as_pid/g_pid_as,
        identity heap), populated at fork() and cleared on child teardown;
        pid_for_current()/as_for_pid() resolve it.
      * libc/signal.cc kill(): a kill targeting a live fork-child pid now routes
        the signal-handler thread into the TARGET backend's address space (and
        reads the TARGET's signal table) so PostgreSQL's latch_sigurg_handler
        runs where selfpipe_writefd resolves to the TARGET's pipe -- the correct
        cross-backend SIGURG latch wakeup.  Process-level notifies (the fork-
        synthesized SIGCHLD a child raises to the postmaster) still run in AS0,
        unchanged.

(D) park_timers per-CPU parked-list not migration-coherent -> intrusive-list
    double-insert (the prior report's symbolized WALL 2).
    Signature (predicted):
      Assertion failed: !safemode_or_autounlink || node_algorithms::inited(...)
        boost/intrusive/list.hpp push_back:273
        sched::cpu::park_timers(sched::thread&)  <- reschedule_from_interrupt
    Root cause: commit 1041518e5 parks an app thread's app-stack timers off the
    per-CPU list on switch-out and links the thread onto a per-CPU
    cpu::parked_threads list, guarded only by a single per-thread _timers_parked
    bool.  But a PARKED (blocked/preempted) thread can be MIGRATED to another CPU
    (load_balance for a queued thread; thread::pin for a waiting/queued thread)
    while still linked on its SOURCE cpu's parked list.  unpark/complete then
    erase from the WRONG cpu's list, or park re-push_back()s a still-linked node
    -> the intrusive-list safe-link double-insert assert.
    FIX (core/sched.cc + include/osv/sched.hh, #if CONF_fork): track the owning
    cpu (thread::_parked_cpu); every erase (unpark_timers, thread::complete)
    targets t._parked_cpu->parked_threads; every migration point (load_balance
    and both thread::pin cases -- all of which run ON the source cpu, which is
    the owning cpu) calls cpu::unlink_parked() to drop the thread from its source
    parked list BEFORE it can run/park elsewhere, keeping _timers_parked set so
    the AS-local timer resume still fires on switch-in.  park_timers asserts
    !is_linked() before push_back.  This corrects 1041518e5 (a #1456 candidate).

Also fixed while making the demonstration reproducible:
(E) /dev/urandom never seeded at startup -> "could not generate random cancel
    key" failed backends at connect (RACILY -- pre-existing on clean HEAD, NOT a
    fork bug, NOT one of the walls, but it blocked reliable multi-connection PG).
    Root cause: the software CSPRNG (yarrow) starts UNSEEDED and only seeds once
    the harvest thread accumulates enough entropy; until then a
    read(/dev/urandom) blocks in randomdev_block() -> msleep(PCATCH), and with
    signals unblocked (PG unblocks right before pg_strong_random) that becomes an
    EINTR retry loop that can outlast the seeding, so the read never completes.
    FIX (drivers/random.cc, #ifdef __x86_64__, NOT fork-gated): when the CSPRNG
    is not yet seeded but the CPU has RDRAND (a hardware CSPRNG needing no
    accumulation window), satisfy the read directly from RDRAND -- cryptographic-
    ally secure, and /dev/{u,}random is usable from the very first read.

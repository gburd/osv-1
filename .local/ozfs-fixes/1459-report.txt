[BUILD ITERATION - aarch64 fixes needed]
Fix 1 (aarch64 code, committed): libc/arch/aarch64/atomic.h
  A userspace `#include <atomic.h>` (from OpenZFS zfs_context.h:101) resolves to
  libc/arch/aarch64/atomic.h (the OSv-internal libc header), NOT libspl's atomic.h,
  because the global `CFLAGS += -I libc/arch/$(arch)` and gcc's -I/-isystem dedup
  (libspl/include appears as both -I and -isystem -> demoted to system position).
  The aarch64 libc header (unlike x64's self-contained one) pulls in <machine/atomic.h>
  and the old bsd opensolaris sys/types.h, both kernel-only -> userspace ZFS TUs break
  (machine/atomic.h not found + conflicting typedefs zoneid_t/o_mode_t/minor_t/... ).
  FIX: gate those two includes under #if defined(_KERNEL)||defined(__OSV_CORE__) and
  give a_fetch_add a __atomic_fetch_add() fallback for userspace. aarch64-only; x64
  file untouched (byte-identical). Cleared ALL libzfs userspace compile errors.

Fix 2 (builder ENV, not code): Fedora-39 osv/builder image was missing zlib-devel
  (setup.py did not install it). libzfs_sendrecv.c #include <zlib.h> failed. Installed
  zlib-devel in the builder image. NOT a source change - environment gap only.

[BLOCKER - pre-existing #1423 patch-series defect, arch-INDEPENDENT]
  Fresh-clone `git apply modules/open_zfs/patches/*.patch` FAILS at patch 0030:
    error: patch failed: module/zfs/arc.c:7980 / patch does not apply
  Root cause: patch 0030's arc.c hunks at lines 4756 (arc_reduce_target_size_noshrink)
  and 7980 (arc_set_limits arc_c_min cap) are BYTE-IDENTICAL DUPLICATES of patch 0009's

  This is arch-INDEPENDENT: git apply of the same patches against the same pinned
  submodule (zfs-2.4.3, 83020cf8) fails the same way for x86_64 and aarch64. It is
  masked on previously-built trees by the .osv-patches-applied stamp (apply is skipped
  when the stamp exists), which is why x86_64 "verified byte-identical" (that tree had
  the stamp; the apply step never re-ran).
  => This is a #1423 bug (0030 must drop its duplicate 4756+7980 hunks, keeping only

[BOOT ATTEMPT 1 - aarch64 clock ceiling blocker]
  zfs_builder VM booted (OSv v0.57.0-399-g73f1e533) then ABORTED:
    "arm_clock(): read invalid frequency 000000003e95ba80" -> Halting.
  0x3e95ba80 = 1,050,000,000 Hz = 1.05 GHz. arch/aarch64/arm-clock.cc capped the ARM
  generic-timer freq at 1000*MHZ (1GHz); AWS Graviton3 (Neoverse-V1) passes 1.05GHz
  through to the guest under KVM, so the sanity check aborted boot. Pre-existing OSv
  aarch64 limitation (not ZFS), but blocks booting ANY aarch64 image on Graviton.
  FIX (aarch64-only, x64 untouched): raise ceiling 1000->2000 MHZ. Rebuilding...

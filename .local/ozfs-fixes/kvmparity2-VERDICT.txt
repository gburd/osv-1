THE PRIOR KVM AGENT (8b6c2d4e) WAS RIGHT THAT ITS IMAGE DID NOT SERVE, BUT ITS DIAGNOSIS WAS WRONG TWICE:
  (1) It was NOT the "bgworker fork wall". The hang is in IpcMemoryCreate (ipci.c:211) ->
      PGSharedMemoryCreate -> CreateAnonymousSegment -> mmap(MAP_SHARED|MAP_ANONYMOUS) (sysv_shmem.c:622),
      which is BEFORE any fork. The "registering background worker" log line it read as the fork wall is
      merely the last debug1 line; debug5 shows the real last line is "invoking IpcMemoryCreate(size=...)".
  (2) The fix is a ONE-LINE CONFIG: shared_memory_type=sysv. PG's default mmap-anonymous-shared path
      hangs OSv (99.9% CPU spin, gdbstub can't even get a safe-point) -- the roadmap-documented
      "endless 2MB-populate loop at slot 64" (sigusr-fault.txt). SysV shm uses a different OSv path that
      does NOT loop, so the postmaster reaches ready. Reproduced the mmap-hang across smp {1,8},
      shared_buffers {16MB,128MB,1GB}, huge_pages=off, dsm=posix -- ALL hang on mmap; sysv SERVES.

TWO RESIDUAL WALLS remain (both roadmap-known, NEITHER is "can't serve"):
  WALL 1 (worked around here): mmap(MAP_SHARED|MAP_ANON) startup hang -> shared_memory_type=sysv.
  WALL 2 (still open): catalog-read-zero across forked backends. Any query needing a shared-buffers
    catalog page fails in the FORKED backend:
      "select current_database()" -> FATAL: role "postgres" does not exist   (pg_authid page read as 0)
      "select count(*) from pg_class" -> FATAL: index "pg_authid_rolname_index"/"pg_class_oid_index"
                                          contains unexpected zero page at block 0
    "select 1" works (no catalog lookup). This is the roadmap "multi-backend catalog-read coherence wall"
    (ROADMAP line 1466) -- the SysV shm segment is not coherently visible to OSv's fork-emulated backends.
  ALSO: under memory pressure OSv's own page allocator faulted:
    page_fault in memory::page_range_allocator::remove <- page_pool::l2::free_batch <- l2::unfill <-
    l2::fill_thread  (an OSv kernel MM crash, "Aborted") -- a separate kernel fault surfaced by the load.

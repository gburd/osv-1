THE WALLS + FIXES (gdb-proven), with classification tags
================================================================================

WALL (B) -- forked-backend writes produced ZERO block I/O  [fork-stack / CONF_fork]
  Symptom: `insert; checkpoint` returned success but the virtio-blk WRITE
  counter never moved and rows were invisible; txg_syncing/synced frozen across
  samples.
  gdb root cause: the txg_sync thread (AS0)
    spa_sync -> dsl_pool_sync -> dmu_objset_sync -> dnode_sync -> dbuf_sync_list
    -> dbuf_sync_leaf -> dbuf_write -> zio_nowait -> zio_issue_async
    -> taskq_dispatch_ent -> taskqueue_enqueue -> mtx_lock(&tq->tq_mutex)
  faulted (lock xadd) on a mutex at 0x3000000b4fd0 -- the FORK COW ARENA (PTE in
  AS0: present, writable=ro).  The struct taskqueue (with tq_mutex) had been
  calloc()'d from the per-process COW arena (std_malloc routes app-context
  allocations there); after PG's first fork() that page is COW-write-protected
  in AS0, so the AS0 sync thread's atomic write to tq_mutex took a COW write
  fault, grabbed the kernel vma_list_mutex for write, and DEADLOCKED against a
  forked backend holding it for read across a demand fault.  vma_list_mutex
  showed WRITER_LOCK held, txg frozen.
  Fix (bsd/sys/kern/subr_taskqueue.c, #if CONF_fork): wrap the struct taskqueue
  + tq_threads allocations in fork_kernel_heap_push/pop so a ZFS taskqueue (used
  by AS0 sync/zio threads AND forked backends) is one identity-heap object,
  never COW.  conf_fork=0 byte-identical (TQ_KHEAP macros are no-ops).
  Effect: the WRITE counter now moves and dirty data reaches the disk.

Read-after-write coherence -- "unexpected data beyond EOF in block 0"  [#1423 / OpenZFS]
  Symptom: after the deadlock fix, `insert` reached the disk but a subsequent
  read failed: ERROR: unexpected data beyond EOF in block 0 of relation
  "base/5/16384"; count(*) still 0.
  gdb/source root cause: zfs_vop_write() (OSv vop_write bridge in
  module/os/osv/zfs/zfs_vnops_os.c) calls zfs_write(), which updates the ZFS
  logical size zp->z_size but NOT the OSv vnode cached vp->v_size.
  zfs_vop_read()/zfs_vop_cache() bound reads with vp->v_size (the ONLY reference
  to it), so a file-extending write followed by a read of the new region
  returns EOF.  Wrong even for single-process OpenZFS; latent because earlier
  bring-up used write-close-reopen or in-bounds reads.
  Fix: new modules/open_zfs/patches/0028-*.patch (NOT a direct submodule edit)
  refreshes vp->v_size = zp->z_size after every successful VREG write.
  Effect: insert -> select round-trips (rows visible).

Crash-restart shmem false positive -- "pre-existing shared memory block ... still in use"  [OSv/libc]
  Symptom: after a crash+reboot PG refused to start:
    FATAL: pre-existing shared memory block (key 34, ID 5) is still in use
  root cause: OSv shmctl(IPC_STAT) unconditionally returned 0 and shmat(dup(fd))
  mapped whatever unrelated file occupied that fd number.  PG's
  PGSharedMemoryIsInUse() probe of the STALE id from postmaster.pid therefore
  got SHMSTATE_ANALYSIS_FAILURE ("still in use") instead of ENOENT.  Wrong even
  single-process (any PG restart after a crash).
  Fix (libc/shm.cc): shm_fd_is_segment() = dynamic_cast<mmu::shm_file*>(fd);
  shmctl(IPC_STAT/IPC_RMID) and shmat return EINVAL for a non-shm id, so
  PGSharedMemoryAttach concludes SHMSTATE_ENOENT and PG runs automatic recovery.
  Effect: PG does WAL redo and reaches "ready" after a crash.

rwlock read-waiter cross-AS SIGSEGV under load  [fork-stack / CONF_fork]
  Symptom: pgbench -i -s 50 bulk COPY aborted at ~20%:
    Aborted; rwlock::wake_pending_readers(unsigned)+82 <- rwlock::wunlock()+58
    <- (app frames) <- taskqueue_thread_loop  (RDX=0x200000afc6e0 = COW app stack)
  root cause: rwlock::rlock() registers a pending reader as a
  lockfree::linked_item<thread*> that is a LOCAL on the waiter's stack, pushed
  onto the SHARED _read_waiters queue.  A forked backend blocking as a reader
  leaves its read_waiter at a COW-private app-stack VA; an AS0 writer releasing
  the lock walks _read_waiters in wake_pending_readers() and dereferences that
  VA through AS0 page tables -> SIGSEGV.
  Fix (core/rwlock.cc, #if CONF_fork): mirror the existing
  lfmutex/coherent_wait_record mechanism -- when fork_child_needs_heap_wait_record()
  (forked-child caller, or any live child AS while the AS0 parent waits),
  allocate the linked_item from the identity kernel heap; the waiter frees it
  after waking.  AS0-only default keeps the on-stack fast path.  conf_fork=0
  byte-identical.
  Effect: pgbench -i -s 50 completes 100% (5,000,000 rows).

REMAINING WALL (worked around, not fixed) -- PG PARALLEL QUERY hangs [PG-on-OSv, next]
  A seqscan of the 5M-row table spawned PG parallel workers and hung: the
  scanning backend + workers parked in dbuf_read -> zio_nowait -> zio_vdev_io_*
  -> condvar::wait with block I/O fully drained (g_blk_submitted==completed,
  frozen) -- a lost wakeup in the parallel-worker/DSM coordination path (the
  workers coordinate via dynamic shared memory + shared-memory queues, whose
  cross-AS/fork wakeup is not yet coherent).  Setting
  max_parallel_workers_per_gather=0 makes ALL reads work (count(*) over 5,000,000
  rows returns instantly).  Non-parallel single-backend and 8-client
  concurrent read/write workloads are unaffected.  Likely the same
  identity-heap/cross-AS-wakeup class as the four fixed walls, in the DSM/shm
  queue path; bounded, next to fix.  Also: SIGHUP to the postmaster returns
  ESRCH (kill by PID), which breaks pg_reload_conf()/autovacuum-worker launch --
  a PID/signal mapping issue on OSv, benign with autovacuum=off.

REGRESSION TEST -- tests/tst-fork-zfs-write.cc  (CONF_fork gated; zfs-only-tests)
================================================================================
A forked child writes+fsyncs a 40 KiB file (spans several ZFS records, and is
file-extending) on a ZFS mount (/tmp); the parent, after reaping the child,
stat()s the grown size and reads back the exact bytes -- asserting the durable
round-trip.  Reproduces BOTH write-path walls on a buggy kernel (taskqueue COW
deadlock -> hang/no-persist; v_size beyond-EOF -> short read) and passes with
the fixes.  SKIPs on conf_fork=0.
